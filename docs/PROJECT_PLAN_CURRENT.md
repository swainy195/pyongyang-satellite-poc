# 평양 위성정보 분석 PoC 프로젝트 기획서

> 작성일: 2026-08-08  
> 프로젝트: pyongyang-satellite-poc  
> 목적: 평양 및 북한 행정구역, 시설, 동향 데이터와 위성 기반 지표를 결합해 지도 기반 분석 및 근거 기반 보고서를 생성하는 PoC를 구축한다.

## 1. 프로젝트 개요

이 프로젝트는 북한 평양 지역을 중심으로 행정경계, 시설 정보, 시설 속성, 동향 데이터를 통합하고, 향후 VIIRS 야간조도 및 Hansen 산림손실 데이터를 결합해 공간 변화 분석을 수행하는 것을 목표로 한다.

최종 사용자는 웹 지도에서 행정구역과 시설을 탐색하고, 특정 기간의 변화량을 비교하며, 시설 및 동향 근거를 바탕으로 분석 보고서를 생성할 수 있어야 한다.

## 2. 핵심 목표

1. 북한 행정경계와 시설 데이터를 Supabase/PostgreSQL에 통합 적재한다.
2. 시설, 속성, 동향, 시설-동향 연결 데이터를 조회 가능한 형태로 정규화한다.
3. React와 MapLibre 기반 웹 UI에서 행정구역 및 시설을 시각화한다.
4. Google Earth Engine을 활용해 VIIRS 야간조도와 Hansen 산림손실 통계를 생성한다.
5. 분석 결과와 문서 근거를 결합해 보고서 생성 기능을 구현한다.
6. 데이터 출처, 처리 버전, 근거 ID를 추적해 보고서의 재현성과 검증 가능성을 확보한다.

## 3. 현재 Supabase 적재 상태

2026-08-08 기준 원격 Supabase `Test Project`에서 확인한 public 스키마 테이블과 행 수는 다음과 같다.

| 테이블 | 행 수 | 설명 |
|---|---:|---|
| `admin_boundaries` | 716 | 북한 행정경계 |
| `facilities` | 1,718 | 시설 마스터 |
| `facility_attributes` | 5,585 | 시설별 속성 |
| `trends` | 42,896 | 동향 데이터 |
| `trend_facilities` | 17,525 | 동향-시설 연결 |

추가 확인 결과:

| 점검 항목 | 값 | 의미 |
|---|---:|---|
| `attributes_linked` | 5,585 | 시설 속성이 시설 ID에 연결됨 |
| `trend_facility_links` | 17,525 | 동향-시설 연결 데이터 존재 |
| `facilities_with_geom` | 0 | 시설 geometry는 아직 생성되지 않음 |

현재 원격 Supabase에는 로컬 마이그레이션에 정의된 일부 테이블이 아직 없다. 예를 들어 `documents`, `reports`, `nightlight_stats`, `forest_stats`, `import_batches`, `raw_import_rows` 등은 원격 public 스키마에서 확인되지 않았다.

## 4. 주요 데이터

### 4.1 행정경계

- 원천 형식: GeoJSON
- 현재 적재 테이블: `admin_boundaries`
- 확인된 행 수: 716
- 활용 목적: 지도 경계 표시, 행정구역 단위 집계, 시설 공간 매칭

### 4.2 시설 데이터

- 현재 적재 테이블: `facilities`
- 확인된 행 수: 1,718
- 주요 활용: 시설 검색, 시설 상세, 동향 연결, 위성 지표 버퍼 분석
- 현재 이슈: `geom` 값이 비어 있어 지도상의 정확한 점 표시와 공간 분석은 아직 제한됨

### 4.3 시설 속성

- 현재 적재 테이블: `facility_attributes`
- 확인된 행 수: 5,585
- 주요 활용: 시설 상세 정보, 필터링, 보고서 근거

### 4.4 동향 데이터

- 현재 적재 테이블: `trends`
- 확인된 행 수: 42,896
- 주요 활용: 사건/동향 검색, 시설 관련 근거 연결, 보고서 생성

### 4.5 동향-시설 연결

- 현재 적재 테이블: `trend_facilities`
- 확인된 행 수: 17,525
- 주요 활용: 특정 시설과 관련된 동향 이력 조회

## 7. 현재 확인된 이슈

1. `.env`의 `DATABASE_URL` 값에 `DATABASE_URL=DATABASE_URL=...` 형태의 중복 prefix가 있다.
2. 시설 테이블의 `geom` 값이 모두 비어 있어 지도 점 표시와 공간 분석이 제한된다.
3. 원격 Supabase 스키마가 로컬 마이그레이션 파일과 일치하지 않는다.
4. `documents`, `reports`, `nightlight_stats`, `forest_stats` 등 후속 기능용 테이블이 원격에 아직 없다.
5. 기존 일부 문서 파일은 문자 인코딩이 깨져 있어 정리된 문서로 재작성할 필요가 있다.

## 9. 완료 기준

PoC의 1차 완료 기준은 다음과 같다.

1. 원격 Supabase에 필요한 스키마가 정렬되어 있다.
2. 시설 위치가 지도에 표시된다.
3. 행정경계와 시설을 기준으로 데이터 탐색이 가능하다.
4. 시설별 속성과 동향 연결을 조회할 수 있다.
5. 최소 1개 위성 지표가 행정구역 또는 시설 단위로 조회된다.
6. 선택한 대상에 대한 근거 기반 Markdown 보고서를 생성할 수 있다.

## 10. 운영 주의사항

- Supabase service role key와 LLM API key는 클라이언트 번들에 포함하지 않는다.
- `.env` 파일은 Git에 커밋하지 않는다.
- 비밀번호가 포함된 DB URL은 터미널 명령줄 인자로 넘기지 않는다.
- 위성 데이터는 자료별 가용 기간과 해상도 차이를 보고서에 명시한다.
- 동향 데이터와 위성 변화의 동시 발생을 인과관계로 단정하지 않는다.
